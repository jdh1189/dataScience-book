    📋 프로젝트 기획 — 주제 선정과 계획 수립¶

    Part 5 | [2권] 나만의 데이터 과학 프로젝트 · 21차시

    🎯 이 장에서 배우는 것¶

    • 자신의 관심사에서 데이터로 답할 수 있는 질문을 만들어 프로젝트 주제를 선정할 수 있다
    • 주제 선정의 3가지 기준(흥미, 데이터 확보 가능성, 분석 가능성)으로 후보를 평가할 수 있다
    • 프로젝트 계획서 템플릿을 활용하여 체계적인 계획서를 작성할 수 있다
    • 동료 피드백을 반영하여 주제와 계획을 구체화할 수 있다

    💡 왜 이걸 배우나요?¶

    여러분은 지금까지 데이터를 수집하고, 정리하고, 시각화하고, 분석하는 기술을 차근차근 배워왔습니다. 이제 드디어 나만의 프로젝트를 시작할 차례입니다! 🎉

    그런데 잠깐, 건물을 짓기 전에 설계도가 필요하듯 프로젝트를 시작하기 전에 기획이 필요합니다. "뭘 하지?"에서 멈추는 것이 아니라, "무엇을, 왜, 어떤 데이터로, 언제까지" 할지 구체적으로 정하는 과정이 바로 프로젝트 기획입니다.

    🏗️ 생각해보기: 여행을 떠날 때 목적지도, 교통편도, 일정도 없이 그냥 출발하면 어떻게 될까요? 프로젝트도 마찬가지입니다. 좋은 기획이 좋은 결과의 절반을 만듭니다.

    실제로 데이터 과학자들도 업무 시간의 30~40%를 기획과 문제 정의에 사용합니다. 이 장에서 탄탄한 기획 능력을 익히면, 앞으로 어떤 프로젝트든 자신 있게 시작할 수 있습니다.

    📚 핵심 개념¶

    개념 1: 데이터로 답할 수 있는 질문 만들기 🔍¶

    1. 비유로 시작

    의사에게 "저 어디가 아픈 것 같아요"라고 말하면 진단이 어렵습니다. 하지만 "일주일 전부터 오른쪽 무릎이 계단을 오를 때 아파요"라고 말하면 훨씬 정확한 진단이 가능하죠. 프로젝트 질문도 마찬가지입니다. 막연한 궁금증을 데이터로 측정하고 답할 수 있는 구체적인 질문으로 바꿔야 합니다.

    2. 정확한 정의

    데이터 질문(Data Question)이란, 데이터를 수집하고 분석하면 답을 구할 수 있는 형태의 질문입니다. 좋은 데이터 질문은 세 가지 조건을 충족합니다.

    • 구체적: 무엇을, 누구에 대해, 어떤 기간에 알고 싶은지 명확함
    • 측정 가능: 숫자나 범주로 표현할 수 있음
    • 답을 구할 수 있음: 실제로 데이터를 모아 분석할 수 있음

    3. 예시로 확인

    • ❌ 막연한 질문: "급식이 맛있을까?"

    • ✅ 데이터 질문: "우리 학교 학생 100명에게 이번 달 급식 만족도(1~5점)를 조사하면, 요일별로 만족도에 차이가 있을까?"

    • ❌ 막연한 질문: "유튜브를 많이 보면 성적이 떨어질까?"

    • ✅ 데이터 질문: "우리 반 학생들의 주중 유튜브 시청 시간과 중간고사 평균 성적 사이에 상관관계가 있을까?"

    개념 2: 주제 선정의 3가지 기준 ⚖️¶

    1. 비유로 시작

    신발을 고를 때 예쁘기만 하면 안 되죠. 발에 맞아야 하고, 가격도 적당해야 합니다. 프로젝트 주제도 세 가지 기준을 동시에 만족해야 성공적으로 완수할 수 있습니다.

    2. 정확한 정의

    graph TD A["🎯 좋은 프로젝트 주제"] --- B["❤️ 흥미<br/>내가 진짜 궁금한가?"] A --- C["📦 데이터 확보 가능성<br/>데이터를 구할 수 있는가?"] A --- D["🔧 분석 가능성<br/>내 실력으로 분석 가능한가?"] B --- E["동기 부여 유지"] C --- F["공공데이터, 설문, 크롤링 등"] D --- G["배운 도구로 처리 가능한 규모"]
    • ❤️ 흥미: 프로젝트는 몇 주간 지속됩니다. 내가 정말 알고 싶은 주제여야 끝까지 해낼 수 있습니다.
    • 📦 데이터 확보 가능성: 아무리 좋은 주제라도 데이터를 구할 수 없으면 시작할 수 없습니다. 공공데이터 포털, 설문조사, 웹 크롤링 등 데이터 출처가 있어야 합니다.
    • 🔧 분석 가능성: 지금까지 배운 도구(Python, pandas, matplotlib 등)로 다룰 수 있는 크기와 형태의 데이터여야 합니다.

    3. 예시로 확인

    • 주제 A — "K-pop 아이돌 그룹의 음원 성적과 SNS 팔로워 수의 관계"
    • 흥미 ⭐⭐⭐ / 데이터 확보 ⭐⭐⭐(음원 차트, SNS 공개 데이터) / 분석 가능성 ⭐⭐⭐ → 적합!
    • 주제 B — "전 세계 심해 생물의 유전자 분석"
    • 흥미 ⭐⭐⭐ / 데이터 확보 ⭐(전문 장비 필요) / 분석 가능성 ⭐(고급 생물정보학) → 부적합

    개념 3: 프로젝트 계획서 템플릿 📝¶

    1. 비유로 시작

    요리할 때 레시피가 있으면 재료 준비부터 완성까지 순서대로 할 수 있습니다. 프로젝트 계획서는 데이터 과학 프로젝트의 레시피입니다.

    2. 정확한 정의

    프로젝트 계획서는 다음 6가지 항목으로 구성됩니다.

    graph LR A["1️⃣ 문제 정의"] --> B["2️⃣ 가설 설정"] B --> C["3️⃣ 데이터 출처"] C --> D["4️⃣ 분석 방법"] D --> E["5️⃣ 예상 결과"] E --> F["6️⃣ 일정표"]
    • 1️⃣ 문제 정의: 무엇을 알고 싶은지 데이터 질문 형태로 작성
    • 2️⃣ 가설 설정: 분석 전에 예상하는 답 (예: "시청 시간이 길수록 성적이 낮을 것이다")
    • 3️⃣ 데이터 출처: 어디서, 어떻게 데이터를 모을 것인지 (URL, 설문 방법 등)
    • 4️⃣ 분석 방법: 어떤 기법을 사용할 것인지 (시각화, 상관분석, 그룹 비교 등)
    • 5️⃣ 예상 결과: 어떤 형태의 결과물이 나올지 (그래프 종류, 발견할 패턴 등)
    • 6️⃣ 일정표: 주차별 또는 차시별로 할 일을 정리

    3. 예시로 확인

    🗒️ 예시 계획서 요약 - 문제 정의: 서울시 구별 공원 면적과 미세먼지 농도 사이에 관계가 있을까? - 가설: 공원 면적이 넓은 구일수록 미세먼지 농도가 낮을 것이다 - 데이터 출처: 서울 열린데이터광장(공원 면적), 에어코리아(미세먼지) - 분석 방법: 산점도 시각화, 상관계수 계산 - 예상 결과: 음의 상관관계를 보여주는 산점도 - 일정표: 1주차 데이터 수집 → 2주차 전처리·분석 → 3주차 시각화·보고서

    개념 4: 동료 피드백과 주제 구체화 🤝¶

    1. 비유로 시작

    거울 없이 자기 얼굴을 완벽하게 볼 수 없듯이, 자기 아이디어의 빈틈도 혼자서는 찾기 어렵습니다. 동료의 눈이 바로 아이디어의 거울 역할을 합니다.

    2. 정확한 정의

    동료 피드백(Peer Feedback)은 같은 수준의 학습자끼리 서로의 계획을 검토하고 건설적인 의견을 주고받는 과정입니다. 효과적인 피드백의 원칙은 다음과 같습니다.

    • 구체적으로: "좋아요" 대신 "데이터 출처가 명확해서 실행 가능성이 높아 보여요"
    • 질문으로: "이 데이터에서 결측값이 많으면 어떻게 처리할 계획인가요?"
    • 대안 제시: "설문 대신 공공데이터를 활용하면 시간을 절약할 수 있을 것 같아요"

    3. 예시로 확인

    graph TD A["주제 후보 3개 리스트업"] --> B["모둠 내 발표<br/>(1인당 3분)"] B --> C["동료 피드백<br/>(질문 + 제안)"] C --> D["피드백 반영하여<br/>최종 주제 1개 확정"] D --> E["계획서 수정·보완"]

    💬 피드백 예시 대화

    발표자: "편의점 도시락 가격과 칼로리의 관계를 분석하고 싶어요."

    피드백 1: "재밌는 주제네! 그런데 데이터를 어떻게 모을 거야? 직접 조사?"

    피드백 2: "편의점 앱에서 가격과 영양 정보를 크롤링하면 빠를 것 같아."

    발표자: "아, 그 방법이 있구나! 데이터 출처를 수정해야겠다."

    🔨 따라하기¶

    이번 실습에서는 Python으로 프로젝트 계획서를 구조화하고, 주제 평가 점수를 자동으로 계산하는 도구를 만들어 봅니다.

    Step 1: 브레인스토밍 — 질문 리스트 만들기¶

    먼저 "내가 가장 궁금한 것"을 데이터 질문 형태로 최소 3개 적어봅시다.

    # 브레인스토밍: 데이터 질문 후보 리스트
my_questions = [
    "우리 학교 학생들의 수면 시간과 시험 성적 사이에 관계가 있을까?",
    "서울시 지하철역별 승하차 인원이 가장 많은 시간대는 언제일까?",
    "유튜브 인기 동영상의 제목 글자 수가 조회수에 영향을 미칠까?"
]

print("🧠 나의 데이터 질문 후보:")
for i, q in enumerate(my_questions, 1):
    print(f"  {i}. {q}")

    🧠 나의 데이터 질문 후보:
  1. 우리 학교 학생들의 수면 시간과 시험 성적 사이에 관계가 있을까?
  2. 서울시 지하철역별 승하차 인원이 가장 많은 시간대는 언제일까?
  3. 유튜브 인기 동영상의 제목 글자 수가 조회수에 영향을 미칠까?

    🖊️ 알아보기: 질문을 쓸 때 "~일까?", "~관계가 있을까?"처럼 의문문 형태로 쓰면 분석 목표가 더 명확해집니다.

    Step 2: 주제 평가 — 3가지 기준으로 점수 매기기¶

    # 주제 평가 (각 기준 1~5점)
candidates = {
    "수면 시간 vs 시험 성적": {"흥미": 5, "데이터_확보": 3, "분석_가능성": 4},
    "지하철 승하차 시간대":   {"흥미": 3, "데이터_확보": 5, "분석_가능성": 5},
    "유튜브 제목 vs 조회수":  {"흥미": 5, "데이터_확보": 4, "분석_가능성": 4},
}

print("📊 주제 평가 결과:")
print(f"{'주제':<25} {'흥미':>4} {'확보':>4} {'분석':>4} {'총점':>4}")
print("-" * 45)

best_topic = ""
best_score = 0

for topic, scores in candidates.items():
    total = sum(scores.values())
    print(f"{topic:<25} {scores['흥미']:>4} {scores['데이터_확보']:>4} {scores['분석_가능성']:>4} {total:>4}")
    if total > best_score:
        best_score = total
        best_topic = topic

print(f"\n🏆 최고 점수 주제: '{best_topic}' (총 {best_score}점)")

    계획서에 빠진 항목이 없는지 자동으로 체크하는 도구를 만듭니다.

    # 계획서 완성도 점검
def check_plan(plan):
    required = ["프로젝트_제목", "문제_정의", "가설", 
                "데이터_출처", "분석_방법", "예상_결과", "일정표"]

    print("✅ 계획서 완성도 점검:")
    missing = []

    for item in required:
        if item in plan and plan[item]:
            print(f"   ✔ {item}: 작성 완료")
        else:
            print(f"   ✖ {item}: ⚠️ 미작성!")
            missing.append(item)

    score = (len(required) - len(missing)) / len(required) * 100
    print(f"\n   📈 완성도: {score:.0f}%")

    if score == 100:
        print("   🎉 완벽한 계획서입니다!")
    else:
        print(f"   📝 다음 항목을 보완하세요: {', '.join(missing)}")

check_plan(project_plan)
