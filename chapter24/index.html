    📖 Chapter 24: 프로젝트 마무리 — 보고서 작성과 최종 발표¶

    Part 5 | [2권] 나만의 데이터 과학 프로젝트 — 마지막 차시

    🎯 이 장에서 배우는 것¶

    • 코랩 노트북을 문제 정의 → 데이터 소개 → 전처리 → 분석 결과 → 결론 순서로 체계적으로 정리할 수 있다
    • 핵심 시각화에 해석 문장을 덧붙여 독자가 바로 이해할 수 있는 보고서를 작성할 수 있다
    • 5~7분 분량의 발표 스크립트를 구성하고 효과적으로 발표할 수 있다
    • 동료 프로젝트를 평가하고 건설적인 피드백을 제공할 수 있다
    • 프로젝트 전체를 돌아보는 회고록을 작성할 수 있다

    💡 왜 이걸 배우나요?¶

    요리 대회를 떠올려 봅시다. 아무리 맛있는 음식을 만들어도, 접시에 아무렇게나 담아 내놓으면 심사위원은 감동하지 않습니다. 플레이팅(담음새) 이 중요한 이유입니다.

    데이터 과학도 똑같습니다. 여러분이 지금까지 데이터를 수집하고, 정제하고, 분석한 과정은 "맛있는 요리를 만드는 과정"에 해당합니다. 이제 남은 일은 그 결과를 보기 좋게 담아내고, 사람들 앞에서 설명하는 것입니다.

    현업 데이터 과학자들도 분석 시간의 30% 이상을 보고서 작성과 커뮤니케이션에 씁니다. 아무리 뛰어난 분석도 다른 사람이 이해하지 못하면 가치가 절반으로 줄어듭니다.

    이 장을 마치면, 여러분은 "데이터를 다루는 사람"에서 "데이터로 이야기하는 사람" 으로 한 단계 성장하게 됩니다. 🎓

    📚 핵심 개념¶

    개념 1: 데이터 분석 보고서의 구조¶

    🍔 비유로 시작하기

    햄버거를 생각해 보세요. 위쪽 빵(도입) → 채소(데이터 소개) → 패티(분석 핵심) → 소스(해석) → 아래쪽 빵(결론). 각 재료가 정해진 순서로 쌓여야 맛있는 햄버거가 됩니다. 보고서도 마찬가지입니다.

    📌 정확한 정의

    데이터 분석 보고서란 문제 → 데이터 → 방법 → 결과 → 결론 의 흐름을 따라, 분석 과정과 발견을 제3자가 재현하고 이해할 수 있도록 정리한 문서입니다.

    ✏️ 예시로 확인 — 보고서 뼈대

    flowchart TD A["1️⃣ 제목 & 소개\n프로젝트 이름, 팀원, 날짜"] --> B["2️⃣ 문제 정의\n어떤 궁금증을 풀려고 했는가?"] B --> C["3️⃣ 데이터 소개\n출처, 크기, 주요 컬럼 설명"] C --> D["4️⃣ 전처리 과정\n결측치, 이상치, 변환 등"] D --> E["5️⃣ 분석 결과 & 시각화\n그래프 + 해석 문장"] E --> F["6️⃣ 결론 & 한계점\n답변, 아쉬운 점, 다음 과제"]

    알아보기 💡: 코랩 노트북은 마크다운 셀(글)과 코드 셀(분석)을 번갈아 배치할 수 있어서, 그 자체가 훌륭한 보고서 도구입니다. 별도의 워드 문서가 필요 없습니다!

    각 섹션이 담아야 할 핵심 내용을 정리하면 다음과 같습니다.

    • 제목 & 소개 — 프로젝트명, 팀원 이름, 작성일, 한 줄 요약
    • 문제 정의 — "왜 이 주제를 선택했는가?", 구체적 질문 1~2개
    • 데이터 소개 — 출처 URL, 행·열 수, 주요 컬럼 설명
    • 전처리 과정 — 결측치 처리, 타입 변환, 파생 변수 생성 등
    • 분석 결과 & 시각화 — 핵심 그래프 3~5개, 각 그래프 아래 해석 1~2문장
    • 결론 & 한계점 — 질문에 대한 답, 한계, 향후 개선 방향

    개념 2: 시각화에 해석 덧붙이기¶

    🖼️ 비유로 시작하기

    미술관에 그림만 걸어 두면, 관람객은 "예쁘다" 정도만 느낍니다. 하지만 옆에 작품 해설 카드가 있으면 그림의 의미를 깊이 이해합니다. 그래프 옆에 붙이는 해석 문장이 바로 이 "해설 카드"입니다.

    📌 정확한 정의

    시각화 해석이란, 그래프가 보여 주는 패턴·추세·이상점을 한두 문장의 자연어로 설명하여, 독자가 그래프를 보지 않아도 핵심을 파악할 수 있게 하는 것입니다.

    ✏️ 예시로 확인 — 좋은 해석 vs 나쁜 해석

    • ❌ 나쁜 해석: "위 그래프는 막대그래프이다."
    • ✅ 좋은 해석: "서울의 1인당 공원 면적은 부산보다 1.8배 넓으며, 전국 17개 시도 중 3위에 해당한다. 이는 서울시의 대규모 도시공원 정책과 관련이 있는 것으로 보인다."

    좋은 해석의 공식은 다음과 같습니다.

    • 무엇이 보이는가 (사실)
    • 얼마나 차이가 나는가 (수치)
    • 왜 그럴 수 있는가 (추정 원인)

    개념 3: 효과적인 발표 구성¶

    🎬 비유로 시작하기

    영화 예고편은 2분 안에 관객의 마음을 사로잡습니다. 전체 줄거리를 다 보여 주지 않고, 가장 인상적인 장면 몇 개만 골라서 보여 주죠. 5~7분 발표도 "예고편 전략"이 필요합니다.

    📌 정확한 정의

    데이터 프로젝트 발표란, 보고서의 모든 내용을 읽어 주는 것이 아니라, 핵심 스토리라인을 추려서 청중이 "문제 → 발견 → 의미"를 자연스럽게 따라올 수 있도록 구성하는 커뮤니케이션 활동입니다.

    ✏️ 예시로 확인 — 5분 발표 타임라인

    flowchart LR A["0:00~0:30\n🎣 흥미 유발\n질문 or 놀라운 사실"] --> B["0:30~1:30\n🔍 문제 & 데이터\n왜 이 주제? 어떤 데이터?"] B --> C["1:30~3:30\n📊 핵심 결과\n그래프 2~3개 + 해석"] C --> D["3:30~4:30\n💡 결론 & 한계\n답변과 아쉬운 점"] D --> E["4:30~5:00\n❓ Q&A 안내\n질문 유도"]

    생각해보기 🤔: 발표에서 가장 중요한 슬라이드는 몇 번째일까요? 바로 첫 번째(흥미 유발) 와 마지막(결론) 입니다. 사람들은 처음과 끝을 가장 오래 기억합니다!

    발표 팁 체크리스트

    • 슬라이드 한 장에 핵심 메시지 1개만
    • 글자 크기는 24pt 이상 (뒷자리에서도 읽힘)
    • 그래프에 제목·축 라벨·단위 반드시 표시
    • 원고를 읽지 말고, 청중을 바라보며 이야기하기
    • "음…", "그러니까…" 같은 군더더기 줄이기

    개념 4: 동료 평가와 회고¶

    🪞 비유로 시작하기

    운동선수는 경기 후 경기 영상을 되돌려 봅니다. 잘한 플레이는 강화하고, 실수한 부분은 교정하기 위해서입니다. 프로젝트 회고도 같은 역할을 합니다. "내 경기 영상"을 돌려보는 시간입니다.

    📌 정확한 정의

    • 동료 평가(Peer Review): 같은 수업을 듣는 친구가 여러분의 프로젝트를 정해진 기준에 따라 평가하고 피드백을 제공하는 활동
    • 회고(Retrospective): 프로젝트 전체를 돌아보며 잘한 점(Keep), 아쉬운 점(Problem), 다음에 시도할 점(Try) 을 정리하는 반성적 글쓰기

    ✏️ 예시로 확인 — KPT 회고 프레임

    flowchart TD K["🟢 Keep\n잘한 점, 계속할 것"] --> P["🟡 Problem\n아쉬운 점, 어려웠던 것"] P --> T["🔵 Try\n다음에 새로 시도할 것"]

    알아보기 💡: 동료 평가에서 "잘했어!"만 쓰는 것은 피드백이 아닙니다. "막대그래프 색상이 너무 비슷해서 구분이 어려웠어. 색상을 더 대비되게 바꾸면 좋겠어." 처럼 구체적 관찰 + 개선 제안이 진짜 피드백입니다.

    🔨 따라하기: 최종 보고서 완성하기¶

    이제 여러분의 코랩 노트북을 최종 보고서 형태로 정리합니다. 아래 단계를 하나씩 따라 해 보세요.

    Step 1: 보고서 뼈대 마크다운 작성하기¶

    코랩 노트북 맨 위에 새 텍스트 셀을 추가하고, 아래 마크다운을 붙여 넣으세요. 꺾쇠 괄호(< >) 안의 내용을 여러분의 프로젝트에 맞게 수정합니다.

    # 코랩 노트북의 "텍스트 셀"에 아래 마크다운을 입력하세요

# ============================================================
# 아래는 마크다운 원문입니다. 텍스트 셀에 직접 붙여넣으세요.
# ============================================================

markdown_template = """
# 🎓 <프로젝트 제목을 입력하세요>

**작성자**: <이름>
**작성일**: <날짜>
**데이터 출처**: <URL 또는 출처 설명>

---

## 1. 문제 정의
<왜 이 주제를 선택했는지, 어떤 질문에 답하려 하는지 2~3문장으로 작성>

## 2. 데이터 소개
<데이터 출처, 행·열 수, 주요 컬럼 이름과 의미 설명>

## 3. 전처리 과정
<결측치 처리, 타입 변환, 파생 변수 등 핵심 작업만 요약>

## 4. 분석 결과
<핵심 시각화 + 해석 문장을 코드 셀과 텍스트 셀로 번갈아 배치>

## 5. 결론 및 한계점
<질문에 대한 답변, 분석의 한계, 향후 개선 방향>
"""

print("보고서 템플릿이 준비되었습니다!")
print("위 내용을 텍스트 셀에 붙여넣고, <> 부분을 수정하세요.")

    정리하기 📌: 이 뼈대를 먼저 만들어 두면, 나머지 코드 셀을 어디에 배치해야 할지 명확해집니다. "지도를 먼저 그리고 여행을 떠나는 것"과 같습니다.

    Step 2: 데이터 소개 섹션 작성하기¶

    "2. 데이터 소개" 아래에 코드 셀을 추가하여, 데이터의 기본 정보를 출력합니다.

    import pandas as pd

# === 여러분의 데이터 파일 경로로 바꾸세요 ===
df = pd.read_csv('my_project_data.csv')

# 데이터 크기 확인
print(f"📦 데이터 크기: {df.shape[0]}행 × {df.shape[1]}열")
print()

# 처음 5행 미리보기
print("🔍 데이터 미리보기:")
df.head()

    # 컬럼별 데이터 타입과 결측치 확인
print("📋 컬럼 정보:")
print(f"  - 전체 컬럼 수: {len(df.columns)}")
print(f"  - 결측치가 있는 컬럼 수: {df.isnull().any().sum()}")
print()

# 각 컬럼의 결측치 수 출력
missing = df.isnull().sum()
missing_cols = missing[missing > 0]
