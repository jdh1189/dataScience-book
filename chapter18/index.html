    Chapter 18: 자유 주제 최종 프로젝트 발표 및 성찰¶

    Part 4 | [2권] 데이터 과학 프로젝트 — 18차시 (최종)

    🎯 이 장에서 배우는 것¶

    • 데이터 과학 프로젝트의 전 과정(문제 정의→수집→분석→모델링→시각화→결론)을 하나의 노트북으로 완성할 수 있다
    • 발표 자료를 5단계 구조로 체계적으로 구성할 수 있다
    • 동료 평가 루브릭을 활용하여 피드백을 주고받을 수 있다
    • 1~18차시 학습 여정을 성찰하고, 데이터 과학의 전이 가능성을 인식할 수 있다

    💡 왜 이걸 배우나요?¶

    요리 대회를 생각해 보세요. 아무리 맛있는 음식을 만들어도 심사위원 앞에서 요리 과정과 맛의 포인트를 설명하지 못하면 좋은 점수를 받기 어렵습니다. 데이터 과학도 마찬가지입니다. 분석 결과를 다른 사람이 이해할 수 있게 전달하는 것이 프로젝트의 마지막 퍼즐 조각입니다.

    이번 최종 차시에서는 여러분이 직접 선택한 주제로 수행한 프로젝트를 발표하고, 동료의 프로젝트를 평가하며, 18차시에 걸친 데이터 과학 학습 여정 전체를 성찰합니다. 이 과정을 거치면 "데이터로 문제를 발견하고 해결하는 사람"으로서 한 단계 성장한 자신을 발견할 수 있습니다.

    📚 핵심 개념¶

    개념 1: 프로젝트 발표의 5단계 구조 🎤¶

    비유 — 추리 소설의 구성

    좋은 추리 소설은 ① 사건 발생 → ② 단서 수집 → ③ 추리 과정 → ④ 범인 발견 → ⑤ 에필로그 순서로 전개됩니다. 데이터 과학 발표도 비슷한 흐름을 따릅니다.

    정확한 정의

    프로젝트 발표는 다음 5단계를 순서대로 따릅니다.

    • 1단계 — 문제 정의: "왜 이 주제를 선택했는가?", "어떤 질문에 답하려 하는가?"
    • 2단계 — 데이터 소개: 어디서, 어떤 데이터를 수집했는지, 데이터의 크기·변수·출처
    • 3단계 — 분석 과정: 전처리, 탐색적 분석, 모델링 등 핵심 과정을 시각화와 함께 설명
    • 4단계 — 핵심 발견: 분석에서 도출한 가장 중요한 인사이트 1~3개
    • 5단계 — 결론 및 한계: 질문에 대한 답, 한계점, 후속 연구 제안

    예시로 확인

    주제가 "우리 학교 급식 만족도 분석"이라면: 1단계 → "급식 메뉴별 만족도 차이가 있을까?" 2단계 → "설문지 120명 응답, 메뉴·맛·양·위생 4개 변수" 3단계 → "결측치 제거 → 메뉴별 평균 만족도 시각화 → 상관분석" 4단계 → "한식 메뉴가 양식 메뉴보다 만족도가 0.8점 높았다" 5단계 → "표본이 1학년에 집중되어 전체 학교를 대표하기 어렵다"

    flowchart LR A["1️⃣ 문제 정의"] --> B["2️⃣ 데이터 소개"] B --> C["3️⃣ 분석 과정"] C --> D["4️⃣ 핵심 발견"] D --> E["5️⃣ 결론 및 한계"]

    개념 2: 동료 평가 루브릭 📋¶

    비유 — 체조 심사 점수판

    체조 경기에서 심사위원은 '난이도', '실행 정확도', '예술성' 등 기준별로 점수를 매깁니다. 주관적인 "좋다/나쁘다"가 아니라 구체적 기준(루브릭)이 있어야 공정한 평가가 됩니다.

    정확한 정의

    루브릭(Rubric): 평가 항목별로 수준(상·중·하)의 기준을 미리 정의한 채점 기준표. 평가자의 주관을 줄이고, 피드백의 구체성을 높입니다.

    프로젝트 동료 평가 루브릭 예시

    • 문제 정의 (1~5점): 질문이 명확하고 데이터로 답할 수 있는가?
    • 데이터 활용 (1~5점): 데이터 출처가 신뢰할 만하고, 전처리가 적절한가?
    • 분석 깊이 (1~5점): 단순 기술통계를 넘어 의미 있는 분석을 시도했는가?
    • 시각화 품질 (1~5점): 그래프가 정보를 효과적으로 전달하는가?
    • 발표 전달력 (1~5점): 논리적 흐름, 시간 관리, 청중과의 소통

    💡 알아보기: 루브릭은 "평가를 위한 도구"이기도 하지만, 프로젝트를 시작하기 전에 읽으면 "무엇을 잘해야 하는지" 미리 파악하는 가이드가 됩니다.

    개념 3: 효과적인 시각화 발표 슬라이드 원칙 📊¶

    비유 — 교통 표지판

    운전 중에 교통 표지판은 한눈에 핵심 정보를 전달합니다. 글씨가 빽빽한 표지판은 본 적이 없죠? 발표 슬라이드도 마찬가지입니다.

    정확한 정의

    발표 시각 자료는 "1 슬라이드 = 1 메시지" 원칙을 따릅니다.

    • 텍스트는 최소화: 한 슬라이드에 핵심 문장 1~2줄
    • 그래프에 제목과 라벨 필수: 축 이름, 단위, 범례가 빠지면 청중이 읽을 수 없음
    • 색상은 3가지 이내: 너무 많은 색은 혼란을 줌
    • 글자 크기 18pt 이상: 뒷자리에서도 읽을 수 있도록

    예시로 확인

    flowchart TD A["❌ 나쁜 슬라이드"] --> A1["글씨가 빽빽함"] A --> A2["그래프에 제목 없음"] A --> A3["색상 7가지 사용"] B["✅ 좋은 슬라이드"] --> B1["핵심 문장 1줄"] B --> B2["그래프에 제목+라벨"] B --> B3["색상 2~3가지"]

    개념 4: 학습 여정 성찰 (메타인지) 🪞¶

    비유 — 등산 후 정상에서 뒤돌아보기

    산을 오르는 동안은 발밑만 보지만, 정상에 도착하면 지나온 길 전체가 보입니다. 성찰은 학습의 정상에서 뒤돌아보는 과정입니다.

    정확한 정의

    메타인지(Metacognition): "내가 무엇을 알고, 무엇을 모르는지"를 아는 것. 학습 여정 성찰은 다음 질문에 답하는 것입니다.

    • 처음 데이터 과학을 접했을 때와 지금, 나의 역량은 어떻게 변했는가?
    • 1~4단원에서 배운 개념 중 프로젝트에 실제로 쓰인 것은 무엇인가?
    • 가장 어려웠던 순간과 그것을 어떻게 해결했는가?
    • 다음에 도전하고 싶은 프로젝트는 무엇인가?

    🧠 생각해보기: 성찰을 글로 쓰면 "막연한 느낌"이 "구체적인 자기 이해"로 바뀝니다. 이것이 다음 프로젝트의 출발점이 됩니다.

    🔨 따라하기: 최종 발표 노트북 완성하기¶

    이번 실습에서는 Google Colab 노트북 하나를 발표 자료 겸 보고서로 완성합니다. 아래 코드는 "예시 프로젝트: 서울 기온 데이터로 본 여름 폭염 추세"를 기준으로 작성되어 있습니다. 여러분은 자신의 주제에 맞게 수정하세요!

    Step 1: 노트북 구조 만들기 — 마크다운 셀 작성¶

    Colab에서 텍스트 셀(마크다운)을 활용해 5단계 구조를 만듭니다.

    # 이 내용은 Colab의 "텍스트 셀"에 마크다운으로 작성합니다.
# 아래는 참고용 구조입니다.

presentation_structure = """
# 🌡️ 서울 기온 데이터로 본 여름 폭염 추세

## 1. 문제 정의
- 질문: "서울의 여름 폭염일수는 정말 증가하고 있을까?"
- 선택 이유: 매년 뉴스에서 '역대급 폭염'이라고 하는데, 데이터로 확인하고 싶었다.

## 2. 데이터 소개
- 출처: 기상자료개방포털(data.kma.go.kr)
- 기간: 2000~2023년, 서울 관측소
- 변수: 날짜, 최고기온, 최저기온, 평균기온

## 3. 분석 과정
- (코드와 시각화가 이어서 나옴)

## 4. 핵심 발견
- (분석 결과 요약)

## 5. 결론 및 한계
- (답변, 한계, 후속 연구)
"""
print(presentation_structure)

    Step 2: 예시 데이터 생성 및 전처리¶

    실제 프로젝트에서는 자신의 데이터를 사용하세요. 여기서는 연습용 가상 데이터를 만듭니다.

    import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import matplotlib
matplotlib.rcParams['font.family'] = 'NanumGothic'  # Colab 한글 폰트

# 가상 데이터 생성 (2000~2023년 여름 폭염일수)
np.random.seed(42)
years = list(range(2000, 2024))
# 약간의 증가 추세 + 랜덤 노이즈
heatwave_days = [int(10 + 0.5 * (y - 2000) + np.random.normal(0, 3)) for y in years]
heatwave_days = [max(0, d) for d in heatwave_days]  # 음수 방지

df = pd.DataFrame({'연도': years, '폭염일수': heatwave_days})
print("=== 데이터 미리보기 ===")
print(df.head(10))
print(f"\n전체 행 수: {len(df)}")
print(f"폭염일수 평균: {df['폭염일수'].mean():.1f}일")

    Step 3: 핵심 시각화 만들기¶

    발표에서 가장 중요한 그래프 1~2개를 정성껏 만듭니다.

    fig, ax = plt.subplots(figsize=(10, 5))

# 막대 그래프
ax.bar(df['연도'], df['폭염일수'], color='#FF6B6B', alpha=0.7, label='폭염일수')

# 추세선 (선형 회귀)
z = np.polyfit(df['연도'], df['폭염일수'], 1)
p = np.poly1d(z)
ax.plot(df['연도'], p(df['연도']), color='#C0392B', linewidth=2.5,
        linestyle='--', label=f'추세선 (기울기: {z[0]:.2f}일/년)')

ax.set_title('서울 여름 폭염일수 추이 (2000~2023)', fontsize=16, fontweight='bold')
ax.set_xlabel('연도', fontsize=12)
ax.set_ylabel('폭염일수 (일)', fontsize=12)
ax.legend(fontsize=11)
ax.set_ylim(0, max(df['폭염일수']) + 5)

plt.tight_layout()
plt.show()

print(f"\n📌 추세선 기울기: 매년 약 {z[0]:.2f}일씩 폭염일수가 변화")

    Step 4: 핵심 발견 정리 및 결론 작성¶

    # 전반기 vs 후반기 비교
first_half = df[df['연도'] < 2012]['폭염일수'].mean()
second_half = df[df['연도'] >= 2012]['폭염일수'].mean()

print("=" * 50)
print("📊 핵심 발견")
print("=" * 50)
print(f"  2000~2011년 평균 폭염일수: {first_half:.1f}일")

    아래 코드를 실행하면 동료 평가를 기록할 수 있는 간단한 양식이 출력됩니다.

    def peer_review(reviewer, presenter):
    """동료 평가 입력 함수"""
    print(f"\n{'='*50}")
    print(f"📋 동료 평가서")
    print(f"  평가자: {reviewer}")
    print(f"  발표자: {presenter}")
    print(f"{'='*50}")

    categories = [
        '1. 문제 정의 (질문이 명확한가?)',
        '2. 데이터 활용 (출처가 신뢰할 만한가?)',
        '3. 분석 깊이 (의미 있는 분석인가?)',
        '4. 시각화 품질 (그래프가 효과적인가?)',
        '5. 발표 전달력 (논리적 흐름인가?)'
    ]

    scores = []
    for cat in categories:
        # 실제 수업에서는 input()으로 입력받습니다
        # 여기서는 예시 점수를 사용합니다
        score = np.random.randint(3, 6)  # 3~5점 예시
        scores.append(score)
        print(f"  {cat}: {score}점")

    total = sum(scores)
    print(f"\n  ✨ 총점: {total}/25점")
    print(f"  💬 한 줄 피드백: 시각화가 깔끔하고 결론이 명확했습니다!")
    return total

# 예시 실행
peer_review("김학생", "이학생")

    # ===== 최종 프로젝트 발표 & 성찰 통합 코드 =====

import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import matplotlib
matplotlib.rcParams['font.family'] = 'NanumGothic'

# --- 1. 데이터 준비 ---
np.random.seed(42)
years = list(range(2000, 2024))
heatwave_days = [max(0, int(10 + 0.5*(y-2000) + np.random.normal(0,3))) for y in years]
df = pd.DataFrame({'연도': years, '폭염일수': heatwave_days})

# --- 2. 핵심 시각화 ---
fig, ax = plt.subplots(figsize=(10, 5))
ax.bar(df['연도'], df['폭염일수'], color='#FF6B6B', alpha=0.7, label='폭염일수')

z = np.polyfit(df['연도'], df['폭염일수'], 1)
p = np.poly1d(z)
ax.plot(df['연도'], p(df['연도']), color='#C0392B', linewidth=2.5,
        linestyle='--', label=f'추세선 (기울기: {z[0]:.2f}일/년)')

ax.set_title('서울 여름 폭염일수 추이 (2000~2023)', fontsize=16, fontweight='bold')
ax.set_xlabel('연도', fontsize=12)
ax.set_ylabel('폭염일수 (일)', fontsize=12)
ax.legend(fontsize=11)
plt.tight_layout()
plt.show()

# --- 3. 핵심 발견 ---
first_half = df[df['연도'] < 2012]['폭염일수'].mean()
second_half = df[df['연도'] >= 2012]['폭염일수'].mean()
print(f"전반기 평균: {first_half:.1f}일 → 후반기 평균: {second_half:.1f}일")
print(f"추세선 기울기: 매년 약 {z[0]:.2f}일 변화")

# --- 4. 동료 평가 ---
def peer_review(reviewer, presenter):
    categories = ['문제정의','데이터활용','분석깊이','시각화품질','발표전달력']
    scores = [np.random.randint(3,6) for _ in categories]
    for c, s in zip(categories, scores):
        print(f"  {c}: {s}점")
    print(f"  총점: {sum(scores)}/25점")

peer_review("김학생", "이학생")

    실수 1: 분석 과정 없이 결론만 발표하기 😵

    "폭염이 늘었습니다."라고 결론만 말하면 청중은 왜, 어떻게 그 결론에 도달했는지 알 수 없습니다. 반드시 데이터 → 분석 방법 → 근거 → 결론 순서를 보여주세요.

    실수 2: 한계점을 숨기기 🙈

    "한계점이 있으면 발표가 약해 보이지 않을까?"라고 걱정하는 학생이 많습니다. 하지만 한계점을 스스로 인식하고 밝히는 것이 오히려 분석의 신뢰성을 높이는 행위입니다. 모든 연구에는 한계가 있습니다.

    실수 3: 그래프에 제목과 축 라벨을 빼먹기 📉

    코드를 작성할 때는 데이터를 이해하고 있으므로 제목이 없어도 괜찮다고 느낄 수 있습니다. 하지만 청중은 처음 보는 그래프입니다. set_title(), set_xlabel(), set_ylabel()은 반드시 포함하세요.

    실수 4: 성찰을 "재미있었다"로 끝내기 😅

    "프로젝트가 재미있었다"는 성찰이 아닙니다. 구체적으로 무엇을 배웠고, 무엇이 어려웠고, 다음에 어떻게 하겠다는 것까지 써야 진정한 성찰입니다.
