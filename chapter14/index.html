    챕터 14: 프로젝트 준비 - 데이터 과학 적용과 데이터 적합성¶

    🎯 이 장에서 배우는 것¶

    • 실생활 문제 중 데이터 과학을 적용할 수 있는 분야와 한계를 판별할 수 있다
    • 데이터의 적합성을 충분성·신뢰성·관련성 세 기준으로 평가할 수 있다
    • 프로젝트 계획서(문제 정의 → 데이터 수집 계획 → 분석 방법 선정)를 작성할 수 있다
    • 부적합한 데이터를 식별하고 그 이유를 논리적으로 설명할 수 있다

    💡 왜 이걸 배우나요?¶

    여러분이 요리를 한다고 상상해 보세요. 아무리 실력 좋은 셰프라도 재료가 상했거나, 양이 부족하거나, 아예 다른 요리의 재료를 가져왔다면 맛있는 음식을 만들 수 없습니다.

    데이터 과학도 마찬가지입니다. 아무리 뛰어난 분석 기법을 알고 있어도, 문제에 맞는 데이터를 제대로 준비하지 못하면 프로젝트는 실패합니다. 실제 현업에서도 데이터 과학자들이 가장 많은 시간을 쓰는 단계가 바로 "문제 정의"와 "데이터 준비"입니다.

    이번 장에서는 본격적인 프로젝트에 들어가기 전, "이 문제에 데이터 과학을 적용할 수 있을까?"와 "이 데이터가 정말 쓸 만한가?"를 판단하는 눈을 기릅니다. 이 능력은 앞으로 진행할 두 개의 프로젝트(15장, 16장)뿐 아니라, 여러분이 어떤 데이터 과학 프로젝트를 만나더라도 첫 단추를 잘 끼울 수 있게 해 줍니다.

    📚 핵심 개념¶

    개념 1: 데이터 과학의 적용 가능성과 한계 🔍¶

    1. 비유로 시작

    병원에 갔을 때, 의사는 모든 병을 수술로 치료하지 않습니다. 감기는 약으로, 골절은 깁스로, 심각한 질환만 수술로 치료하죠. 마찬가지로 모든 문제를 데이터 과학으로 해결할 수 있는 것은 아닙니다. 데이터 과학이라는 "도구"가 잘 맞는 문제가 있고, 전혀 맞지 않는 문제도 있습니다.

    2. 정확한 정의

    데이터 과학이 적용 가능한 문제란, 다음 조건을 만족하는 문제입니다.

    • 측정 가능한 데이터가 존재하거나 수집할 수 있다
    • 패턴이나 규칙이 데이터 속에 숨어 있을 가능성이 있다
    • 정답 또는 좋은 결과를 수치로 판단할 수 있다

    반대로, 데이터 과학이 적합하지 않은 경우도 있습니다.

    • 🚫 가치 판단의 문제: "교복을 입어야 하는가?" — 이것은 데이터가 아니라 가치관의 문제입니다
    • 🚫 데이터가 존재하지 않는 문제: 완전히 새로운 현상이라 참고할 과거 기록이 없는 경우
    • 🚫 데이터의 양이 극히 부족한 문제: 전교생 5명인 학교에서 "학생 성적 예측 모델"을 만드는 것
    • 🚫 윤리적으로 수집이 불가능한 데이터: 개인 사생활 침해 없이는 얻을 수 없는 데이터

    3. 예시로 확인

    🟢 적용 가능: "우리 학교 매점에서 어떤 간식이 가장 잘 팔릴까?" → 판매 기록 데이터가 있고, 패턴 분석으로 예측할 수 있다

    🟢 적용 가능: "서울시 자전거 대여소 중 이용량이 가장 많은 곳은?" → 공공데이터포털에 시간별·장소별 대여 기록이 공개되어 있다

    🔴 적용 어려움: "가장 아름다운 그림은 무엇인가?" → '아름다움'은 주관적 가치 판단이라 정답을 수치로 정의하기 어렵다

    🔴 적용 어려움: "내일 수업에서 선생님이 무슨 농담을 하실까?" → 관련 데이터가 존재하지 않는다

    💡 생각해보기: 여러분의 일상에서 "데이터로 해결할 수 있는 문제"와 "데이터로 해결할 수 없는 문제"를 각각 2개씩 떠올려 보세요.

    개념 2: 데이터 적합성의 3가지 기준 📋¶

    1. 비유로 시작

    시험 공부를 한다고 합시다. 교과서(관련성 ✅), 충분한 분량의 문제집(충분성 ✅), 검증된 출판사의 자료(신뢰성 ✅)가 갖춰져야 좋은 점수를 받을 수 있습니다. 엉뚱한 과목의 문제집을 풀거나, 오답이 가득한 자료로 공부하면 오히려 성적이 떨어지겠죠.

    2. 정확한 정의

    데이터 적합성(Data Suitability)이란, 특정 문제를 해결하기에 해당 데이터가 얼마나 적절한지를 평가하는 것입니다. 세 가지 핵심 기준이 있습니다.

    • 충분성(Sufficiency): 분석에 필요한 양이 충분한가?
    • 데이터 건수(행의 수)가 너무 적으면 통계적으로 의미 있는 패턴을 찾기 어렵습니다

    • 일반적으로 수백~수천 건 이상이 바람직합니다

    • 신뢰성(Reliability): 데이터의 출처와 품질을 믿을 수 있는가?

    • 공공기관, 공인된 연구소, 정부 통계 등은 신뢰성이 높습니다
    • 출처 불명의 블로그 데이터, 오래되어 현재와 맞지 않는 데이터는 신뢰성이 낮습니다

    • 결측치(빈 값)나 오류가 지나치게 많으면 신뢰성이 떨어집니다

    • 관련성(Relevance): 해결하려는 문제와 직접 관련이 있는가?

    • "학생 성적 예측"에 "날씨 데이터"를 쓰는 것은 관련성이 낮습니다
    • 변수(컬럼)가 문제의 원인이나 결과와 연결되어야 합니다

    3. 예시로 확인

    다음 상황을 판단해 봅시다.

    문제: "우리 동네 미세먼지 농도를 예측하고 싶다"

    후보 데이터 A — 에어코리아 제공, 최근 3년간 시간별 미세먼지 측정값, 약 26,000건 → 충분성 ✅ | 신뢰성 ✅ | 관련성 ✅ → 적합!

    후보 데이터 B — 개인 블로그에 올린 "체감 공기질" 설문 30건 → 충분성 ❌ | 신뢰성 ❌ | 관련성 △ → 부적합

    후보 데이터 C — 기상청 제공 기온·습도·풍속 데이터 3년치 → 충분성 ✅ | 신뢰성 ✅ | 관련성 △(보조 자료로 활용 가능) → 보조 데이터로 활용

    graph LR A["🔍 데이터 적합성 평가"] --> B["충분성<br/>양이 충분한가?"] A --> C["신뢰성<br/>출처를 믿을 수 있는가?"] A --> D["관련성<br/>문제와 연결되는가?"] B --> E{"세 가지 모두 ✅"} C --> E D --> E E -->|Yes| F["✅ 적합한 데이터"] E -->|No| G["⚠️ 보완 또는 교체 필요"]

    개념 3: 프로젝트 계획서 작성법 📝¶

    1. 비유로 시작

    여행을 떠나기 전에 우리는 계획을 세웁니다. 어디에 갈지(목적지), 어떻게 갈지(교통수단), 무엇을 준비할지(짐 목록)를 정하죠. 계획 없이 떠나면 시간과 돈을 낭비하게 됩니다. 데이터 과학 프로젝트도 똑같습니다.

    2. 정확한 정의

    프로젝트 계획서란, 프로젝트의 전체 흐름을 사전에 설계한 문서입니다. 크게 세 단계로 구성됩니다.

    • ① 문제 정의: 무엇을 알고 싶은가? 왜 중요한가?
    • ② 데이터 수집 계획: 어떤 데이터를, 어디서, 어떻게 구할 것인가?
    • ③ 분석 방법 선정: 어떤 분석 기법을 사용할 것인가?
    graph TD A["1️⃣ 문제 정의<br/>해결하고 싶은 질문은?"] --> B["2️⃣ 데이터 수집 계획<br/>어떤 데이터가 필요한가?"] B --> C["3️⃣ 분석 방법 선정<br/>어떻게 분석할 것인가?"] C --> D["4️⃣ 결과 해석 & 발표<br/>무엇을 알게 되었는가?"]

    3. 예시로 확인 — 계획서 템플릿

    프로젝트 계획서 예시

    📌 프로젝트 제목: 서울시 공공자전거 '따릉이' 이용량 예측

    1단계 — 문제 정의 - 질문: 날씨와 요일에 따라 따릉이 이용량은 어떻게 달라지는가? - 중요한 이유: 자전거 재배치 효율을 높여 시민 불편을 줄일 수 있다 - 기대 결과: 특정 조건에서의 이용량 예측 모델

    2단계 — 데이터 수집 계획 - 주요 데이터: 서울 열린데이터광장 — 따릉이 대여 이력 (월별, 약 100만 건) - 보조 데이터: 기상청 — 일별 기온·강수량 - 수집 방법: CSV 파일 다운로드

    3단계 — 분석 방법 - 탐색적 데이터 분석(EDA): 시간대별·요일별 이용량 시각화 - 상관 분석: 기온·강수량과 이용량의 관계 - 예측 모델: 선형 회귀 또는 의사결정나무

    개념 4: 프로젝트 로드맵 이해하기 🗺️¶

    1. 비유로 시작

    마라톤 선수는 42.195km를 한 번에 뛰지 않습니다. 5km, 10km, 중간 지점, 30km… 이런 식으로 구간을 나누어 페이스를 조절합니다. 프로젝트도 구간별로 나누어야 끝까지 완주할 수 있습니다.

    2. 정확한 정의

    프로젝트 로드맵(Roadmap)은 프로젝트의 시작부터 완료까지 주요 단계와 일정을 시각적으로 보여주는 계획표입니다.

    3. 예시로 확인 — 앞으로의 프로젝트 흐름

    여러분은 이번 장(14장) 이후 두 개의 프로젝트를 진행합니다.

    graph LR A["14장<br/>프로젝트 준비<br/>📋 계획서 작성"] --> B["15장<br/>탐색적 데이터 분석<br/>📊 EDA 프로젝트"] B --> C["16장<br/>예측 모델링<br/>🤖 머신러닝 프로젝트"] C --> D["17장<br/>결과 발표<br/>🎤 스토리텔링"]
    • 14장(지금!): 문제를 정의하고 데이터를 선정하며 계획서를 작성합니다
    • 15장: 데이터를 탐색하고 시각화하여 패턴을 발견합니다

    Step 5: 적합성 종합 보고서 자동 생성¶

    def evaluate_data_suitability(df, target_col, source_info):
    """데이터 적합성을 종합 평가하는 함수"""
    report = {}

    # 1. 충분성
    report['충분성'] = '✅ 적합' if len(df) >= 100 else '❌ 부족'
    report['데이터_건수'] = len(df)

    # 2. 신뢰성
    missing_rate = df.isnull().sum().sum() / (len(df) * len(df.columns)) * 100
    report['신뢰성'] = '✅ 적합' if missing_rate < 5 else '⚠️ 주의'
    report['결측률'] = f"{missing_rate:.1f}%"
    report['출처'] = source_info

    # 3. 관련성
    numeric_cols = df.select_dtypes(include='number').columns.tolist()
    if target_col in numeric_cols:
        numeric_cols.remove(target_col)
    max_corr = df[numeric_cols + [target_col]].corr()[target_col].drop(target_col).abs().max()
    report['관련성'] = '✅ 적합' if max_corr > 0.3 else '⚠️ 약함'
    report['최대_상관계수'] = f"{max_corr:.3f}"

    # 종합
    scores = [report['충분성'], report['신뢰성'], report['관련성']]
    pass_count = sum(1 for s in scores if '✅' in s)
    report['종합'] = '🟢 사용 적합' if pass_count == 3 else ('🟡 보완 필요' if pass_count >= 2 else '🔴 부적합')

    return report

# 평가 실행
result = evaluate_data_suitability(df, '대여건수', '서울 열린데이터광장 (시뮬레이션)')

print("\n" + "=" * 50)
print("📊 데이터 적합성 종합 보고서")
print("=" * 50)
for key, value in result.items():
    print(f"  {key}: {value}")

    실수 3: 상관관계와 인과관계를 혼동한다 🔄

    "아이스크림 판매량이 높은 날 익사 사고가 많다" → 아이스크림이 익사를 유발하는 것이 아니라, 무더운 날씨라는 숨겨진 원인이 둘 다에 영향을 미치는 것입니다. 데이터에서 상관관계를 발견했다고 해서 "A가 B의 원인이다"라고 단정짓지 마세요.

    실수 4: 편향된 데이터를 그대로 사용한다 ⚖️

    설문조사를 특정 반에서만 실시하면, 그 결과는 전체 학교를 대표하지 못합니다. 데이터가 특정 집단, 특정 시기에만 치우쳐 있지 않은지 항상 확인하세요.

    이번 장에서 프로젝트 계획서를 완성했으니, 다음 장에서는 드디어 실제 데이터를 탐색하는 EDA(탐색적 데이터 분석) 프로젝트를 진행합니다. 오늘 작성한 계획서를 손에 들고, 데이터 속에 숨겨진 패턴을 찾아 떠나 봅시다! 🚀
