    Chapter 14. 데이터 과학 프로젝트 1 — 슬기로운 의사 생활¶

    프로젝트 준비: 데이터 과학 적용과 데이터 적합성

    🎯 이 장에서 배우는 것¶

    • 실생활 문제 중 데이터 과학으로 해결할 수 있는 분야와 해결하기 어려운 한계를 구분할 수 있다
    • 데이터의 충분성·신뢰성·관련성 세 가지 기준으로 데이터 적합성을 평가할 수 있다
    • "문제 정의 → 데이터 수집 계획 → 분석 방법 선정" 흐름의 프로젝트 계획서를 작성할 수 있다
    • 부적합한 데이터셋을 식별하고 그 이유를 논리적으로 설명할 수 있다

    💡 왜 이걸 배우나요?¶

    지금까지 1권에서 파이썬 문법, 데이터 정제, 시각화, 머신러닝 기초까지 하나하나 쌓아 왔습니다. 이제 마침내 "진짜 문제" 를 다룰 차례입니다.

    그런데 잠깐, 멋진 기술을 익혔다고 해서 아무 문제나 해결할 수 있을까요?

    🤔 생각해보기: 친구가 "데이터 과학으로 내일 날씨를 100 % 정확하게 맞혀 줘"라고 부탁한다면, 여러분은 어떻게 대답할 건가요?

    데이터 과학은 만능 열쇠가 아닙니다. 어떤 문제에 적용할 수 있고, 어떤 데이터가 적합한지 판단하는 능력 자체가 데이터 과학자의 첫 번째 실력입니다. 병원에서 의사가 환자를 진찰하기 전에 "이 증상이 내가 전문인 분야인지" 먼저 확인하는 것과 같습니다. 이 장의 부제가 슬기로운 의사 생활인 이유이기도 하죠. 🩺

    이번 장에서는 다음 두 프로젝트(15장까지 이어지는 여정)를 제대로 시작하기 위해, 문제를 진단하고 계획을 세우는 방법을 배웁니다.

    📚 핵심 개념¶

    개념 1: 데이터 과학의 적용 가능성과 한계 🔍¶

    1) 비유로 시작¶

    여러분이 슬기로운 의사라고 상상해 봅시다.

    • 환자가 "배가 아파요"라고 오면, 혈액 검사·X선 등 데이터를 모아 진단합니다.
    • 하지만 환자가 "제 인생의 의미를 알려 주세요"라고 물으면? 의사가 아무리 뛰어나도 혈액 검사로 답할 수 없습니다.

    데이터 과학도 마찬가지입니다. 측정 가능한 데이터가 존재하고, 그 데이터 속에 패턴이나 관계가 숨어 있을 때 위력을 발휘합니다.

    2) 정확한 정의¶

    데이터 과학이 잘 맞는 문제란, ① 답을 내리는 데 필요한 데이터를 수집할 수 있고 ② 데이터 안에서 규칙·패턴·상관관계를 찾아 의사결정에 활용할 수 있는 문제를 말합니다.

    반대로, 다음과 같은 경우에는 데이터 과학만으로 해결하기 어렵습니다.

    • 데이터 자체가 존재하지 않거나 수집이 불가능한 문제 — 예: "100년 뒤 화성의 문화는 어떨까?"
    • 윤리적·법적으로 데이터 수집이 금지된 문제 — 예: 동의 없이 개인 의료 기록 수집
    • 정량화할 수 없는 순수 가치 판단 문제 — 예: "초콜릿이 바닐라보다 객관적으로 맛있는가?"
    • 데이터 양이 극도로 부족한 문제 — 예: 역사상 단 한 번 일어난 사건의 원인 분석

    3) 예시로 확인¶

    graph LR A["실생활 문제"] --> B{"데이터<br/>수집 가능?"} B -- 예 --> C{"패턴·관계<br/>존재 가능?"} C -- 예 --> D["✅ 데이터 과학<br/>적용 가능"] C -- 아니오 --> E["⚠️ 적용 어려움"] B -- 아니오 --> E

    적용 가능한 예시 - 🏥 "응급실 방문 환자 수를 요일별로 예측할 수 있을까?" → 과거 방문 기록 데이터 존재, 요일별 패턴 발견 가능 - 🛒 "편의점에서 어떤 상품이 함께 팔릴까?" → POS 매출 데이터 존재, 연관 규칙 분석 가능

    적용 어려운 예시 - 🎨 "이 그림이 감동적인가?" → 감동은 주관적이며 정량 데이터화가 매우 어려움 - 🔮 "내년에 어떤 신기술이 발명될까?" → 아직 존재하지 않는 데이터

    📌 알아보기: 데이터 과학이 "할 수 없는 것"을 아는 것은 "할 수 있는 것"을 아는 것만큼 중요합니다. 한계를 모르면 엉뚱한 결론을 진실이라 믿는 실수를 저지르게 됩니다.

    개념 2: 데이터 적합성 평가 — 충분성·신뢰성·관련성 📋¶

    1) 비유로 시작¶

    다시 의사 비유를 이어가 봅시다.

    • 충분성 — 환자의 체온을 딱 한 번 측정해서 진단을 내릴 수 있을까요? 여러 번, 여러 항목을 검사해야 정확한 진단이 가능합니다.
    • 신뢰성 — 체온계가 고장이라 35 °C와 42 °C를 왔다 갔다 한다면? 검사 결과 자체를 믿을 수 없습니다.
    • 관련성 — 두통을 호소하는 환자에게 발톱 상태만 검사한다면? 아무리 정확한 검사라도 문제와 관련이 없으면 쓸모없습니다.

    2) 정확한 정의¶

    데이터 적합성(Data Suitability)이란, 주어진 데이터가 분석 목표를 달성하기에 적절한지 판단하는 과정입니다. 세 가지 핵심 기준으로 평가합니다.

    ① 충분성 (Sufficiency) - 데이터의 양(행 수)과 다양성(컬럼 수, 시간 범위, 대상 범위)이 분석에 필요한 최소 수준을 충족하는가? - 예: 머신러닝 모델을 훈련하려면 일반적으로 수백~수천 건 이상의 데이터가 필요합니다.

    ② 신뢰성 (Reliability) - 데이터의 출처가 공신력이 있는가? - 데이터에 결측값, 오류, 편향이 심하지 않은가? - 예: 정부 공공데이터포털의 데이터 vs. 출처 불분명한 블로그 데이터

    ③ 관련성 (Relevance) - 데이터가 분석하려는 질문에 직접 관련된 변수를 포함하고 있는가? - 예: "학생의 수면 시간과 성적의 관계"를 분석하는데, 데이터에 수면 시간 컬럼이 없다면 관련성이 없습니다.

    3) 예시로 확인 — 데이터 적합성 체크리스트¶

    아래 체크리스트를 데이터를 고를 때마다 활용하세요.

    ✅ 충분성 체크
   - [ ] 행(데이터 건수)이 100건 이상인가?
   - [ ] 분석에 필요한 주요 변수(컬럼)가 3개 이상 포함되어 있는가?
   - [ ] 시간 범위가 최소 1개월(혹은 분석 목적에 맞는 기간) 이상인가?

✅ 신뢰성 체크
   - [ ] 출처가 공공기관, 학술기관, 공인 기업 등 신뢰할 수 있는 곳인가?
   - [ ] 결측값 비율이 전체의 30 % 이하인가?
   - [ ] 수집 방법이 명시되어 있는가?

✅ 관련성 체크
   - [ ] 분석 질문에 직접 답할 수 있는 변수가 포함되어 있는가?
   - [ ] 데이터의 대상(지역, 연령대 등)이 분석 목적과 일치하는가?
   - [ ] 데이터 수집 시점이 분석하려는 현상과 시간적으로 관련 있는가?

    💡 정리하기: 세 기준 중 하나라도 "아니오"가 나오면 그 데이터는 보완하거나 교체해야 합니다. 세 기준을 모두 만족해야 "적합한 데이터"로 판단합니다.

    graph TB D["후보 데이터셋"] --> S{"충분성<br/>통과?"} S -- Yes --> R{"신뢰성<br/>통과?"} S -- No --> X1["❌ 데이터 추가<br/>수집 필요"] R -- Yes --> V{"관련성<br/>통과?"} R -- No --> X2["❌ 출처 변경<br/>또는 정제 필요"] V -- Yes --> OK["✅ 적합한<br/>데이터!"] V -- No --> X3["❌ 다른<br/>데이터셋 탐색"]

    개념 3: 프로젝트 계획서 작성법 📝¶

    1) 비유로 시작¶

    여행을 떠나기 전에 여행 계획표를 만들어 본 적 있나요?

    • 어디로 갈까? → 문제 정의
    • 교통편과 숙소는? → 데이터 수집 계획
    • 무엇을 할까? → 분석 방법 선정

    계획 없이 떠나면 시간과 돈을 낭비하기 쉽습니다. 데이터 과학 프로젝트도 똑같습니다.

    2) 정확한 정의¶

    프로젝트 계획서란, 데이터 과학 프로젝트를 시작하기 전에 문제 정의, 데이터 수집 계획, 분석 방법을 미리 정리한 문서입니다. 프로젝트의 방향이 흔들리지 않도록 나침반 역할을 합니다.

    계획서는 크게 세 단계로 구성됩니다.

    graph LR A["1단계<br/>문제 정의"] --> B["2단계<br/>데이터 수집 계획"] B --> C["3단계<br/>분석 방법 선정"] C --> D["프로젝트<br/>실행!"]

    1단계 — 문제 정의 - 해결하고 싶은 질문을 한 문장으로 명확하게 적는다. - 나쁜 예: "건강에 대해 분석하고 싶다" (너무 막연함) - 좋은 예: "서울시 구별 응급실 이용 건수에 영향을 미치는 요인은 무엇인가?"

    2단계 — 데이터 수집 계획 - 어떤 데이터가 필요한지, 어디서 구할지, 어떤 형식인지 정리한다. - 앞에서 배운 적합성 체크리스트를 적용한다.

    Step 2: 데이터 적합성 자동 평가 함수 만들기 ✅¶

    앞에서 배운 충분성·신뢰성·관련성 체크리스트를 코드로 구현합니다.

    def evaluate_data_suitability(df, name, min_rows=20, min_cols=3, 
                                max_missing_rate=0.3,
                                required_columns=None):
    """
    데이터 적합성을 평가하는 함수

    매개변수:
        df              : 평가할 데이터프레임
        name            : 데이터셋 이름 (출력용)
        min_rows        : 최소 행 수 (충분성)
        min_cols        : 최소 컬럼 수 (충분성)
        max_missing_rate: 허용 최대 결측값 비율 (신뢰성)
        required_columns: 반드시 포함해야 할 컬럼 리스트 (관련성)
    """

    print(f"\n{'='*55}")
    print(f"🔍 [{name}] 데이터 적합성 평가 결과")
    print(f"{'='*55}")

    results = {}

    # ---- 1. 충분성 평가 ----
    row_ok = len(df) >= min_rows
    col_ok = len(df.columns) >= min_cols
    sufficiency = row_ok and col_ok

    print(f"\n📊 [충분성]")
    print(f"   행 수: {len(df)}건 (기준: {min_rows}건 이상) → {'✅ 통과' if row_ok else '❌ 부족'}")
    print(f"   컬럼 수: {len(df.columns)}개 (기준: {min_cols}개 이상) → {'✅ 통과' if col_ok else '❌ 부족'}")
    results['충분성'] = sufficiency

    # ---- 2. 신뢰성 평가 ----
    total_cells = df.shape[0] * df.shape[1]
    missing_cells = df.isnull().sum().sum()
    missing_rate = missing_cells / total_cells if total_cells > 0 else 0
    reliability = missing_rate <= max_missing_rate

    print(f"\n🔒 [신뢰성]")
    print(f"   결측값: {missing_cells}개 / 전체 {total_cells}개")
    print(f"   결측률: {missing_rate:.1%} (기준: {max_missing_rate:.0%} 이하) → {'✅ 통과' if reliability else '❌ 결측 과다'}")
    results['신뢰성'] = reliability

    # ---- 3. 관련성 평가 ----
    if required_columns:
        existing = [col for col in required_columns if col in df.columns]
        missing_cols = [col for col in required_columns if col not in df.columns]
        relevance = len(missing_cols) == 0

        print(f"\n🎯 [관련성]")
        print(f"   필요 컬럼: {required_columns}")
        print(f"   포함된 컬럼: {existing}")
        if missing_cols:
            print(f"   누락된 컬럼: {missing_cols} → ❌ 관련성 부족")
        else:
            print(f"   모든 필요 컬럼 포함 → ✅ 통과")
    else:
        relevance = True
        print(f"\n🎯 [관련성] 필수 컬럼 미지정 — 수동 확인 필요")
    results['관련성'] = relevance

    # ---- 종합 판정 ----
    all_pass = all(results.values())
    print(f"\n{'─'*55}")
    if all_pass:
        print(f"🎉 종합 판정: ✅ 적합한 데이터입니다!")
    else:
        failed = [k for k, v in results.items() if not v]
        print(f"⚠️  종합 판정: ❌ 부적합 — {', '.join(failed)} 기준 미충족")
    print(f"{'='*55}")

    return results

    💡 이 함수는 앞으로 프로젝트에서 새 데이터셋을 만날 때마다 재사용할 수 있는 범용 도구입니다.

total_cells = df.shape[0] * df.shape[1]
