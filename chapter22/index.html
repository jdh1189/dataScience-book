    프로젝트 실행 (1) — 데이터 수집과 전처리¶

    Part 5 | [2권] 나만의 데이터 과학 프로젝트 — 22차시

    🎯 이 장에서 배우는 것¶

    • 계획서에 명시한 데이터를 실제로 수집하고 코랩(Colab) 환경에 로드할 수 있다
    • 프로젝트 데이터에 맞는 전처리 전략을 스스로 설계하고 실행할 수 있다
    • 전처리 과정과 판단 근거를 코랩 노트북의 마크다운 셀에 기록할 수 있다
    • 전처리 전후 데이터를 비교하여 변화 요약표를 작성할 수 있다

    💡 왜 이걸 배우나요?¶

    여러분은 지난 차시에서 프로젝트 계획서를 완성했습니다. 멋진 설계도를 그려 놓은 것이죠. 그런데 설계도만으로 집이 완성될까요? 이제 실제로 벽돌을 쌓을 차례입니다.

    데이터 과학 프로젝트에서 "벽돌을 쌓는 일"은 데이터를 수집하고 정리하는 것입니다. 현실 세계의 데이터는 놀라울 정도로 지저분합니다. 빈칸이 있고, 이상한 값이 섞여 있고, 형식이 제각각입니다. 요리로 비유하면, 재료를 사 왔는데 흙이 묻어 있고, 상한 부분이 있고, 껍질을 벗겨야 하는 상태인 거죠.

    이 차시에서는 직접 재료를 씻고, 다듬고, 요리할 수 있는 상태로 만드는 전 과정을 경험합니다. 가장 중요한 것은 "왜 이렇게 처리했는지"를 기록하는 습관입니다. 이 기록이 있어야 나중에 누군가(선생님, 동료, 미래의 나 자신)가 여러분의 작업을 이해하고 신뢰할 수 있습니다.

    🔑 핵심 메시지: 데이터 과학자는 전체 프로젝트 시간의 60~80%를 데이터 수집과 전처리에 사용합니다. 이 과정이 분석의 품질을 결정합니다.

    📚 핵심 개념¶

    이번 차시에서 집중할 핵심 개념은 4가지입니다.

    개념 1: 데이터 수집과 로드 — "재료 장보기"¶

    🧩 비유로 시작

    요리를 시작하려면 먼저 마트에 가서 재료를 사 와야 합니다. 그리고 집 주방(작업 환경)에 재료를 꺼내 놓아야 하죠. 데이터 수집은 "마트에서 재료를 고르는 것"이고, 코랩에 로드하는 것은 "주방 조리대 위에 재료를 올려놓는 것"입니다.

    📖 정확한 정의

    • 데이터 수집(Data Collection): 프로젝트 목적에 맞는 데이터를 외부 소스(공공 데이터 포털, 웹사이트, 직접 조사 등)에서 확보하는 과정
    • 데이터 로드(Data Loading): 수집한 데이터 파일을 분석 환경(코랩)에 불러와 프로그래밍으로 다룰 수 있는 상태로 만드는 과정

    🔍 예시로 확인

    여러분의 프로젝트 주제에 따라 데이터 수집 경로가 달라집니다.

    • 공공 데이터 포털(data.go.kr): 교통, 날씨, 인구 등 → CSV, JSON 파일 다운로드
    • Kaggle: 다양한 주제의 정제된 데이터셋 → CSV 파일 다운로드
    • 직접 조사: 설문, 관찰, 측정 → 구글 시트 → CSV 변환
    • 웹 크롤링: 웹사이트에서 정보 추출 → CSV 저장 (이 과정은 고급 단계)

    📌 알아보기: 데이터 소스의 신뢰도도 중요합니다. 정부 기관이나 공인된 연구소에서 제공하는 데이터는 일반적으로 신뢰도가 높습니다. 개인 블로그나 검증되지 않은 출처의 데이터는 주의가 필요합니다.

    코랩에 데이터를 로드하는 방법은 크게 세 가지입니다.

    • 방법 A: 로컬 파일 업로드 — files.upload() 사용
    • 방법 B: 구글 드라이브 연결 — drive.mount() 사용 (추천! 파일이 사라지지 않음)
    • 방법 C: URL에서 직접 불러오기 — pd.read_csv(url) 사용
    # 방법 A: 로컬 파일 업로드
from google.colab import files
uploaded = files.upload()  # 파일 선택 창이 나타남

# 방법 B: 구글 드라이브 마운트 (추천)
from google.colab import drive
drive.mount('/content/drive')
# 이후 경로 예시: '/content/drive/MyDrive/my_project/data.csv'

# 방법 C: URL에서 직접 로드
import pandas as pd
url = "https://example.com/data.csv"
df = pd.read_csv(url)

    💡 생각해보기: 코랩은 세션이 끊어지면 업로드한 파일이 사라집니다. 그래서 구글 드라이브에 데이터를 저장하고 마운트하는 방법 B가 프로젝트 작업에 가장 안정적입니다. 여러분의 프로젝트에는 어떤 방법이 적합할까요?

    개념 2: 데이터 탐색 — "재료 상태 점검"¶

    🧩 비유로 시작

    마트에서 사 온 재료를 조리대에 올려놓았습니다. 바로 칼을 들기 전에 무엇을 하나요? 재료를 하나하나 살펴봅니다. "이 당근은 멀쩡한가?", "양파는 몇 개 샀지?", "상한 건 없나?" 이처럼 데이터도 처리하기 전에 전체 모습을 파악하는 탐색 단계가 필요합니다.

    📖 정확한 정의

    • 데이터 탐색(Data Exploration): 데이터의 구조, 크기, 자료형, 결측값 현황, 기초 통계량 등을 확인하여 전처리 전략을 수립하기 위한 사전 조사

    🔍 예시로 확인 — 탐색 5종 세트

    데이터를 로드한 직후 반드시 확인해야 할 5가지가 있습니다. 이것을 "탐색 5종 세트"라고 부르겠습니다.

    import pandas as pd

# 데이터 로드 (예시: 서울시 미세먼지 데이터)
df = pd.read_csv('/content/drive/MyDrive/my_project/data.csv')

# ① 처음 5행 보기 — 데이터가 어떻게 생겼는지 눈으로 확인
df.head()

# ② 전체 구조 확인 — 행/열 수, 자료형, 결측값 수
df.info()

# ③ 기초 통계량 — 숫자 열의 평균, 최솟값, 최댓값 등
df.describe()

# ④ 결측값 현황 — 각 열에 빈 값이 몇 개인지
df.isnull().sum()

# ⑤ 데이터 크기 확인
print(f"행: {df.shape[0]}개, 열: {df.shape[1]}개")

    📌 알아보기: df.info()의 결과에서 Non-Null Count를 주의 깊게 보세요. 전체 행 수보다 적은 열은 결측값이 있다는 뜻입니다. 또한 Dtype이 object인 열은 문자열 데이터이므로, 숫자여야 하는데 object로 표시되면 변환이 필요합니다.

    탐색 결과를 바탕으로 다음과 같은 질문에 답할 수 있어야 합니다.

    • 데이터 크기: 분석에 충분한 양인가?
    • 결측값: 어떤 열에 얼마나 많은 빈 값이 있는가?
    • 자료형: 각 열의 자료형이 적절한가? (날짜가 문자열로 되어 있진 않은가?)
    • 이상값: 비현실적인 극단값이 있는가?
    • 중복: 같은 데이터가 반복되어 있지 않은가?

    개념 3: 전처리 전략 설계 — "요리 순서 정하기"¶

    🧩 비유로 시작

    재료 상태를 점검했으니 이제 "어떤 순서로 손질할지" 계획을 세워야 합니다. 감자 껍질을 먼저 벗길지, 상한 토마토를 먼저 골라낼지, 양파를 채 썰지 깍둑썰기할지... 이 결정은 최종 요리의 맛을 좌우합니다. 데이터 전처리도 마찬가지입니다. 어떤 문제를 어떤 방법으로 처리할지 미리 전략을 세워야 합니다.

    📖 정확한 정의

    • 전처리 전략 설계(Preprocessing Strategy Design): 탐색 결과를 바탕으로 결측값, 이상값, 자료형, 불필요한 열 등의 문제를 어떤 순서로, 어떤 방법으로 처리할지 계획하는 것

    🔍 예시로 확인

    전처리에서 마주치는 대표적인 문제와 해결 방법을 정리해 보겠습니다.

    🔹 문제 1: 결측값(Missing Values) — 빈칸 처리

    결측값 처리에는 여러 방법이 있으며, 상황에 따라 최선의 방법이 다릅니다.

    • 삭제: 결측값이 있는 행을 제거 → 결측 비율이 매우 낮을 때(5% 미만) 적합
    • 평균/중앙값으로 채우기: 숫자 데이터일 때 → 분포가 고르면 평균, 한쪽으로 치우쳐 있으면 중앙값
    • 최빈값으로 채우기: 범주형 데이터일 때 → 가장 많이 등장하는 값으로 채움
    • 앞/뒤 값으로 채우기: 시계열(시간순) 데이터일 때 → 직전 또는 직후 값으로 채움
    # 결측값 처리 예시들
# 삭제
df_clean = df.dropna(subset=['중요한_열'])

# 평균으로 채우기
df['온도'] = df['온도'].fillna(df['온도'].mean())

# 중앙값으로 채우기
df['가격'] = df['가격'].fillna(df['가격'].median())

# 최빈값으로 채우기
df['지역'] = df['지역'].fillna(df['지역'].mode()[0])

# 앞의 값으로 채우기 (시계열)
df['미세먼지'] = df['미세먼지'].fillna(method='ffill')

    🔹 문제 2: 자료형 변환 — 형태 맞추기

    # 문자열 → 숫자
df['매출'] = pd.to_numeric(df['매출'], errors='coerce')
# errors='coerce': 변환 불가능한 값은 NaN으로 처리

# 문자열 → 날짜
df['날짜'] = pd.to_datetime(df['날짜'])

# 자료형 확인
print(df.dtypes)

    🔹 문제 3: 이상값(Outliers) — 비현실적 값 처리

    # IQR 방법으로 이상값 탐지
Q1 = df['점수'].quantile(0.25)
Q3 = df['점수'].quantile(0.75)
IQR = Q3 - Q1

lower = Q1 - 1.5 * IQR
upper = Q3 + 1.5 * IQR

# 이상값 확인
outliers = df[(df['점수'] < lower) | (df['점수'] > upper)]
print(f"이상값 개수: {len(outliers)}")

# 이상값 제거
df_clean = df[(df['점수'] >= lower) & (df['점수'] <= upper)]

    🔹 문제 4: 불필요한 열 제거 — 안 쓰는 재료 치우기

    # 분석에 불필요한 열 제거
df = df.drop(columns=['Unnamed: 0', '비고', '관리번호'])

    💡 생각해보기: 전처리에서 가장 중요한 것은 "왜"입니다. "결측값을 평균으로 채웠다"보다 "온도 데이터의 결측 비율이 3%로 낮고, 분포가 정규분포에 가까워서 평균으로 채우는 것이 적절하다고 판단했다"라고 기록하는 것이 진정한 데이터 과학자의 태도입니다.

    개념 4: 과정 기록 — "실험 노트 작성"¶

    🧩 비유로 시작

    과학 실험을 할 때 실험 노트를 작성하는 이유는 무엇일까요? 나중에 "왜 이런 결과가 나왔는지" 추적하기 위해서입니다. 또한 다른 사람이 같은 실험을 재현할 수 있도록 하기 위해서이기도 합니다. 데이터 전처리도 마찬가지입니다. 코랩 노트북의 마크다운 셀은 여러분의 실험 노트입니다.

    📖 정확한 정의

    • 과정 기록(Process Documentation): 데이터 전처리의 각 단계에서 무엇을 했는지(What), 왜 했는지(Why), 그 결과가 어떤지(Result)를 체계적으로 기록하는 것
    • 재현 가능성(Reproducibility): 다른 사람(또는 미래의 자신)이 같은 코드와 기록을 보고 동일한 결과를 얻을 수 있는 성질

    🔍 예시로 확인

    코랩에서 마크다운 셀을 추가하는 방법은 간단합니다. 셀 사이에 마우스를 올리면 "+ 텍스트" 버튼이 나타납니다. 클릭하면 마크다운 셀이 추가됩니다.

    ## 1단계: 결측값 처리

### 현황
- `온도` 열: 결측 12개 (전체 500행 중 2.4%)
- `지역` 열: 결측 3개 (전체 500행 중 0.6%)
- `미세먼지` 열: 결측 45개 (전체 500행 중 9.0%)

### 처리 방법과 근거
- **`온도`**: 평균값(22.5°C)으로 대체
  - 근거: 결측 비율이 낮고, 히스토그램 확인 결과 정규분포에 가까움
- **`지역`**: 해당 행 삭제
  - 근거: 지역은 범주형이며, 3행만 삭제하면 되므로 영향 미미
- **`미세먼지`**: 앞의 값으로 채우기(forward fill)
  - 근거: 시계열 데이터이며, 미세먼지 농도는 연속적으로 변하므로 직전 값이 합리적

### 처리 결과
- 처리 전 결측값 총 60개 → 처리 후 0개
- 데이터 행 수: 500 → 497 (3행 삭제)
